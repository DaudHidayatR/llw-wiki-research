## Gap A — Repo-specific verification (research assumed; now verified against live repo @ main)

### A1. `openbao-config` layer — removable, now EVIDENCED
The `openbao-policy-sources` ConfigMap (generated by Flux Kustomization
`30-openbao-config.yaml`) has **ZERO consumers** — no shell script, workload, or
controller reads it. `scripts/commands/openbao.sh:310` reads policies **directly from
Git**: `POLICY_DIR="${PROJECT_ROOT}/kubernetes/clusters/homelab/platform/openbao/configuration/policies"`.
**Conclusion:** research's "remove unless real consumer" is confirmed — remove the layer.

### A2. Policy registry/mappings embedded in Bash — CONFIRMED
`scripts/commands/openbao.sh:319` (`POLICY_FILES=("system-admin|platform/system-admin.hcl" ...)`)
and `:338` (`POLICY_MAPPINGS=(policy|namespace|sa|role|alias ...)`). Exactly the audit P2
flag; the deep research did not verify this repo detail. Move to declarative
`openbao/mappings.yaml`.

### A3. `operations` layer is empty — CONFIRMED
`kubernetes/clusters/homelab/operations/kustomization.yaml` = `resources: []`. Research's
YAGNI removal is now evidenced.

### A4. Headlamp annotations — on the SERVICE (correct removal target)
`apps/headlamp/deployment.yaml` — the `headlamp` Service (lines 11-12) carries
`tailscale.com/expose: "true"` + `tailscale.com/serve: "true"`. Removal target = Service
annotations, matching research.

### A5. ⚠️ OpenBao annotation is ALREADY scoped (research assumed otherwise)
The audit claimed annotating Helm values would hit "ALL chart-generated Services". The
repo ALREADY solves this via a **kustomize patch targeting only `Service/openbao`**
(`platform/openbao/release/helmrelease.yaml:29-41`). So the OpenBao migration is **less
work than the audit assumed** — the annotation is already scoped to the main service;
the change is swapping the annotation approach for a dedicated Tailscale Ingress.
